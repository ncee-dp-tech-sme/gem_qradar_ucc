KEY DESIGN DECISIONS
--------------------
1. Rolling date window (not fixed midnight boundaries):
   The existing GEM_QRadar_UCC connector uses yesterday/today midnight. For a 10-minute
   polling schedule, a rolling [now-interval, now] window is more appropriate — it ensures
   every poll covers exactly the preceding interval with no gaps.

2. recurrence_minutes parameter:
   Instead of hardcoding 600000ms, the interval is a user-visible parameter that must be
   kept in sync with the QRadar log source recurrence schedule. This avoids silent
   missed/duplicated records if the schedule is changed.

3. Numeric JSON key mapping:
   The GEM Activity Log API returns results with numeric string keys ("1"–"7") rather than
   named fields. The LSX uses JsonKeypath patterns like /"4" to extract values, which is
   the correct QRadar JsonKeypath syntax for numeric keys.

4. PostEvent posts results object directly:
   The workflow iterates result.data[] and posts item.results (not the wrapper) so the LSX
   sees a flat { "1": "...", "2": "...", ... } object, matching the JsonKeypath patterns.
